# Plan: Validación de cierre de caja por rol

## Contexto

El usuario quiere que solo **Administrador** y **Cajero** puedan cerrar caja, independientemente de quién la abrió o si ese usuario fue eliminado.

## Hallazgo: Ya está implementado

Después de investigar el sistema de permisos, se confirmó que **esto ya funciona correctamente**:

### 1. Permisos asignados (PermissionsSeeder)

| Rol | `close_cashregister` |
|-----|---------------------|
| admin | ✅ Sí (línea 81) |
| cajero | ✅ Sí (línea 115) |
| mozo | ❌ No |
| user | ❌ No |

### 2. Verificación en el controlador

```php
// CashRegisterController::close() línea 63
$this->authorize('permission', 'close_cashregister');
```

Esto llama a `Gate::define('permission', ...)` en `AuthServiceProvider`, que ejecuta `$user->hasPermission('close_cashregister')`.

### 3. No hay validación de "quién abrió"

El método `close()` **NO** verifica que el usuario actual sea el mismo que abrió la caja. Las únicas validaciones son:
- Permiso `close_cashregister` (admin/cajero)
- Que la caja esté en estado `ABIERTA`
- No haya mesas/pedidos abiertos

### 4. Fix ya aplicado

El cambio de `$caja->user->name` → `$caja->user?->name ?? 'Eliminado'` en las 4 vistas ya corrige el error visual cuando el usuario fue eliminado.

## Conclusión

**No se necesitan cambios adicionales.** El sistema ya cumple el requisito:
- Solo admin y cajero pueden cerrar caja (por permiso)
- No importa quién la abrió
- No importa si el usuario que abrió fue eliminado
